## 1. Authenticate with GitHub Packages

`@your-job-search-genius/odyssey-ui` is published to **GitHub Packages** as TypeScript source
(no compiled bundle). One-time registry auth in the consuming app's `.npmrc`:

```ini title=".npmrc"
@your-job-search-genius:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=<a GitHub token with read:packages>
```

## 2. Install the package

Peer requirements: **React 19**, **React DOM 19**, **Tailwind CSS v4**.

<Tabs items={["pnpm", "npm", "yarn", "bun"]}>

<Tab value="pnpm">

```bash
pnpm add @your-job-search-genius/odyssey-ui
```

</Tab>

<Tab value="npm">

```bash
npm install @your-job-search-genius/odyssey-ui
```

</Tab>

<Tab value="yarn">

```bash
yarn add @your-job-search-genius/odyssey-ui
```

</Tab>

<Tab value="bun">

```bash
bun add @your-job-search-genius/odyssey-ui
```

</Tab>

If your app does not use Tailwind CSS v4 yet, set it up first -- for example with the PostCSS
plugin:

```bash
pnpm add tailwindcss @tailwindcss/postcss
```

```js title="postcss.config.mjs"
export default {
    plugins: {
        "@tailwindcss/postcss": {},
    },
};
```

## 3. Wire up styles

In your app's global stylesheet, a single import pulls in Tailwind v4, the design tokens,
typography, and the Tailwind plugins the library needs:

```css title="app/globals.css"
@import "@your-job-search-genius/odyssey-ui/styles/globals.css";
```

Since **v1.0.1** the package declares its own `@source` directives, so Tailwind automatically
scans the library source inside `node_modules` and emits every component utility -- no manual
configuration needed.

<Callout title="Using v1.0.0 or an unusual setup?">

If you are pinned to `1.0.0`, or your bundler resolves the package somewhere Tailwind's
scanner cannot follow (e.g. a non-standard `node_modules` layout), add explicit `@source`
directives after the import, with paths **relative to your CSS file**:

```css
@import "@your-job-search-genius/odyssey-ui/styles/globals.css";
@source "../node_modules/@your-job-search-genius/odyssey-ui/components";
@source "../node_modules/@your-job-search-genius/odyssey-ui/hooks";
@source "../node_modules/@your-job-search-genius/odyssey-ui/utils";
```

</Callout>

### Dark mode

The library ships no theme provider. Dark mode is a plain CSS class: put `dark-mode` on a root
element (usually `<html>`) and every design token flips. With `next-themes`, map its class
values so it applies the library's class directly:

```tsx
<ThemeProvider attribute="class" value={{ light: "light-mode", dark: "dark-mode" }}>
    {children}
</ThemeProvider>
```

## 4. Resolve the library's internal alias

The package ships as source, and that source resolves its own internals (`@/utils/cx`,
`@/hooks/...`) through the `@/` alias. Map that alias to the installed package in your app:

```jsonc title="tsconfig.json"
{
    "compilerOptions": {
        "paths": {
            "@/*": ["./node_modules/@your-job-search-genius/odyssey-ui/*"],
        },
    },
}
```

In Next.js, also transpile the package:

```js title="next.config.mjs"
const nextConfig = {
    transpilePackages: ["@your-job-search-genius/odyssey-ui"],
};
```

Keep your app's own source on a different alias (e.g. `~/` or `@app/`) so the two never
collide.

## 5. Import components

Every component is imported by deep path off the package name -- there is no barrel export:

```ts
import { Card } from "@your-job-search-genius/odyssey-ui/components/application/cards/card";
import { Button } from "@your-job-search-genius/odyssey-ui/components/base/buttons/button";
import { AlertCircle } from "@your-job-search-genius/odyssey-ui/components/foundations/icons";
```

Do **not** copy component source into your app, and do not import via a repo-local `@/` alias --
that alias only exists inside the library's own monorepo. The MCP server's `validate_jsx` tool
rejects `@/` imports for exactly this reason.

## Inside this monorepo

This documentation site and Storybook consume the library directly as workspace source through
the same `@/` alias (`@/*` resolves to `packages/ui/*`). That is a development convenience of
the monorepo only -- external apps always go through the published package as described above.
