## Semantic color tokens

The library never styles components with raw Tailwind color scales (`text-gray-900`,
`bg-blue-700`, ...). Every component uses semantic utility classes -- `text-primary`,
`bg-secondary`, `border-brand`, `fg-error-primary`, and so on -- defined once in
`styles/theme.css` and automatically adapted for light and dark mode.

## Dark mode

The library's dark mode is driven by a `.dark-mode` class (not Tailwind's default `.dark`)
applied to an ancestor element, matching the `@custom-variant dark (&:where(.dark-mode,
.dark-mode *))` declaration in `styles/theme.css`. This is also how Storybook's theme switcher
works (`.storybook/preview.ts`).

On this site, use the theme toggle in the top navigation to switch between light and dark -- every
live component preview reflects the change immediately, using the library's real dark-mode
styling.

The theme also sets CSS `color-scheme` (`light` on `:root`, `dark` under `.dark-mode`), so native
controls -- scrollbars, date inputs, `NativeSelect` popups -- follow the active theme without any
app code. See [Installation](/docs/getting-started/installation#dark-mode) for applying the class
before first paint.

<Callout type="info">
    In dark mode the `bg-*-secondary` status tokens (`bg-warning-secondary`, `bg-error-secondary`, ...) are solid 600 fills meant for small accents such as
    featured icons. Don't put body text on them; for a tinted text surface use the `bg-*-primary` tokens, which become subtle 950 shades in dark mode. `Alert`
    does exactly this.
</Callout>

## Changing the brand color

To re-theme the entire library, edit the `--color-brand-*` scale (25 through 950) in
`styles/theme.css`. Every component that uses brand-derived semantic tokens (`text-brand-primary`,
`bg-brand-solid`, `fg-brand-primary`, ...) picks up the change automatically -- no per-component
edits required.
